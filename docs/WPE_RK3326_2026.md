# WPE / RK3326 browser research — 2026-09-30

## Target

Fire4Nix targets the R36H/R36S class running ROCKNIX on RK3326/aarch64,
normally at 640x480 under the ROCKNIX Wayland/Sway session.

## Current upstream direction

WPE WebKit 2.54.0 is the current stable WPE series as of this research pass.
WPEPlatform is now the preferred embedding API and the legacy libwpe embedding
API is deprecated upstream. WPE 2.54 also replaces the web-process
TextureMapper compositor with Skia.

Primary references:

- https://wpewebkit.org/release/wpewebkit-2.54.0.html
- https://wpewebkit.org/blog/2026-09-16-wpewebkit-2.54.html
- https://github.com/WebKit/WebKit/blob/main/Tools/MiniBrowser/wpe/main.cpp
- https://github.com/ROCKNIX/distribution

## ROCKNIX browser/runtime findings

Research against the current ROCKNIX source tree found no WPE WebKit or Cog
package in the RK3326 base distribution. The available Chrome addon is declared
x86_64-only, and the ROCKNIX Qt 6 build explicitly disables QtWebEngine and
QtWebView. This means Fire4Nix must not assume that a modern browser engine is
already present on an aarch64 R36H image.

PortMaster's packaging model also favors keeping non-standard libraries inside
the port instead of modifying operating-system libraries. Fire4Nix therefore
uses a self-contained `runtime/aarch64/` gate for the final One File package.

NetSurf remains worth tracking as an emergency low-memory fallback because of
its framebuffer front end, but its web-platform/JavaScript coverage is not a
replacement for WPE WebKit on modern sites.

## Fire4Nix policy

1. Keep WPEPlatform + Wayland as the preferred native path on ROCKNIX.
2. Keep 2.52.6 as the minimum accepted WPE security baseline for compatibility
   testing.
3. Treat WPE 2.54+ as preferred for current development, but do not declare it
   faster on RK3326 until measured on the handheld because the Skia compositor
   is a material graphics-stack change.
4. Keep Cog as a fallback when the native Fire4Nix launcher is unavailable.
5. Do not weaken Chromium/Firefox sandboxing to make a fallback launch easier.
6. Keep WebRTC, media-stream, encrypted media, and developer extras opt-in on
   the 1 GB-class RK3326 target.

## Changes in this pass

The native launcher now follows the WPE MiniBrowser windowing pattern more
closely:

- obtain the WPEPlatform view with webkit_web_view_get_wpe_view();
- obtain its WPEToplevel;
- resize to the configured display dimensions (640x480 by default);
- apply maximize/fullscreen state to the WPE toplevel;
- set the Fire4Nix title;
- fail early when a visible WPEPlatform surface cannot be obtained;
- honor FIRE4NIX_WPE_* runtime toggles that were already exported by the shell
  environment;
- parse --size=WIDTHxHEIGHT instead of silently ignoring it.

A ROCKNIX device smoke-report script was also added. It checks aarch64 userspace,
Wayland availability, WPE version, native ARM64 ELF identity, /dev/dri, and
memory information.

## Device acceptance gate

Before producing the One File Edition, run these checks on the real R36H:

- native launcher is an aarch64 ELF, not a shell placeholder;
- Wayland socket is visible to the PortMaster/EmulationStation launch context;
- first page renders at 640x480 and fullscreen;
- D-pad/analog pointer, A/B, Start/Select and virtual keyboard behavior;
- back/forward/reload/address navigation;
- Wi-Fi DNS/TLS page load;
- audio without killing or replacing the ROCKNIX audio service;
- memory after 1, 3 and 5 representative pages;
- 20-minute browsing soak with web-process crash recovery;
- compare WPE 2.52.6 and 2.54.x on the same device image if both are available.

The One File package remains blocked until a reproducible ARM64 WPE binary and
the on-device acceptance pass exist.

## Follow-up — 2026-10-01: Wayland launch detection

Reviewed upstream WPE, Cog, NetSurf and the Wayland client API. WPE remains
our embedded-browser direction; Cog is a launcher without browser UI, and
NetSurf documentation describes incomplete JavaScript support. Neither is
proof that a ready-made package works on the R36H.

Fixed a launch-selection defect: absolute WAYLAND_DISPLAY socket paths were
incorrectly prefixed with XDG_RUNTIME_DIR, and an unset WAYLAND_DISPLAY did
not check the standard wayland-0 socket. WPE selection, Cog selection and the
device smoke report now share the same socket-path resolver. The resolver
checks socket presence only; compositor connection and rendering still need
the real-device acceptance pass. Inherited WAYLAND_SOCKET descriptors are not
covered by this path-based check.

Regression tests bind real Unix sockets and cover relative paths, absolute
paths without XDG_RUNTIME_DIR, default names, missing sockets and ordinary
files. They run in the host CI job. No performance numbers or device
compatibility claims are inferred from these host checks.
